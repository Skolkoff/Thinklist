# WORKFLOW.md
## SciVisE / Thinklist — AI Agent Execution Workflow

Версия: 1.0  
Статус: FINAL  
Связанный документ: `AGENTS.md`  
Среда: Cursor / Codex / Docker

---

## 1. Назначение Workflow

Данный workflow определяет **строгий, пошаговый порядок действий AI-агента** при работе над проектом SciVisE / Thinklist.

Workflow обязателен к исполнению и предотвращает:
- потерю контекста,
- хаотичные правки,
- «слом» интеграции frontend ↔ backend ↔ ML,
- преждевременный переход между этапами.

---

## 2. Общий цикл работы агента (Mandatory Loop)

Агент **ВСЕГДА** работает по следующему циклу:

1. **Read**
2. **Plan**
3. **Implement**
4. **Verify**
5. **Document**
6. **Mark & Stop**

Переход к следующему шагу разрешён **только после завершения предыдущего**.

---

## 3. Step-by-step Workflow

### STEP 1 — Read (Анализ контекста)

Агент обязан:

- прочитать `AGENTS.md` полностью;
- определить текущий активный этап (I–V);
- проверить статус задач в `INTEGRATION_TASKS.md` или `BACKEND_TASKS.md`;
- зафиксировать **ровно одну** задачу для выполнения.

❌ Запрещено:
- выполнять код без чтения документов;
- брать более одной задачи.

---

### STEP 2 — Plan (Планирование)

Агент обязан сформировать план из **3–7 атомарных шагов**.

Формат плана (обязательный):
```text
Task: I2.1 — Add nginx /api proxy
Goal: Enable frontend → backend communication without CORS
Files:
 - frontend/nginx.conf
Verify:
 - curl http://localhost:5173/api/health

❌ Запрещено:
	•	писать код без плана;
	•	менять архитектуру без фиксации цели.

⸻

STEP 3 — Implement (Реализация)

Агент выполняет только действия из плана.

Разрешанные действия:
	•	правка кода;
	•	добавление конфигураций;
	•	обновление env-файлов;
	•	локальные refactor’ы без изменения API-контрактов.

❌ Запрещено:
	•	выходить за рамки задачи;
	•	выполнять оптим
